## 1. システム基本情報 & SEO・AIO/GEO仕様

- **システム名称**: トク退｜退職日計算ナビ
- **システム目的**: ユーザーが「今考えている退職日」「退職区分」「有給残日数」「年収区分」「退職後の進路」等を入力するだけで、労働・社会保険関係法令に基づいた**金銭面で有利な退職日**および手取り損益額（円表示）を算出し、指定日のままだといくら損をするか／変更するといくら得をするかを可視化する完全無料シミュレーター。あわせて実務期限を「何月何日に何をするか」という行動形式で提示する。
- **ターゲット層**: 転職・退職・定年退職・療養離職を検討中または決定した会社員・公務員・シニア層（スマホからの利用が9割以上を想定）

> **【v17.0 表現改訂】** v16.0までの「**理想の**退職日」という表現は、金銭最適解をユーザーの価値観に押し付ける表現であるため全廃する。退職日は健康状態・次の入社日・家族の事情等、金銭以外の要因で決まることのほうが多い。UI・出力文言・OGP・構造化データのすべてにおいて「**金銭面で有利な退職日**」「**手取りが最大になる退職日**」等の限定表現を用いること。

### SEO / AIO・GEO 対策設定

| 項目 | 内容 |
|---|---|
| ページタイトル | `トク退｜退職日計算ナビ` |
| メタディスクリプション | 退職希望日・有休残日数・年収・定年等の条件を入力するだけで、最終出社日・資格喪失日・手取り差額（具体金額）・住民税や退職金の注意点を自動算定。登録不要、完全無料の退職日シミュレーター。 |
| 構造化データ（JSON-LD） | `SoftwareApplication`（常時）／ `HowTo`・`FAQPage`・`Legislation`（診断結果に応じ `schema_generator.js` で動的DOM挿入） |

| AIO/GEO引用ブロック | STEP 1 冒頭に、LLM参照用のアンサーファースト文（`.aio-answer`）を配置。根拠法規を**正しい条文番号で**明記（第9章参照） |

> **【v17.0 重要 / 構造化データの目的の再定義】**
> v16.0はHowTo・FAQPage構造化データをGoogleのリッチリザルト獲得目的として記述していたが、**この前提は既に成立しない。**
>
> - **HowToリッチリザルト**：2023年9月にデスクトップを含め完全廃止済み
> - **FAQリッチリザルト**：2026年5月7日に検索結果への表示が停止。Search Consoleのレポート・リッチリザルトテストのサポートは2026年6月、Search Console APIのサポートは2026年8月に終了
>
> ただし**マークアップ自体は有効なschema.orgの型として残っており、LLMによる引用・理解の助けになるため撤去はしない。**
>
> **したがってv17.0では、HowTo / FAQPage / Legislation の実装目的を「Google検索での見た目の強化」ではなく「AI検索（ChatGPT / Perplexity / Claude / AI Overviews）における引用獲得」と再定義する。** 実装者・SEO担当は、これらのスキーマを入れてもGoogle検索結果の表示は一切変わらないことを前提に工数を配分すること。
>
> Google検索結果の表示に実際に寄与するのは `SoftwareApplication` / `Organization` / `Article` および**可視コンテンツそのものの品質**である。ここに優先的に投資すること。

- **キャッシュ制御**: `_headers` で `Cache-Control: public, max-age=0, must-revalidate` を設定

> **【実装方針：47都道府県テーブルはβ版で全件実装する】**
>
> 全国平均（9.9%）固定での暫定実装は行わない。令和8年度の料率は **9.21%（新潟）〜10.55%（佐賀）** と1.34ポイントの幅があり、標準報酬月額30万円の場合、本人負担で月約2,000円の差が生じる。これは1ヶ月分の社会保険料比較において約5%の誤差にあたり、**判定が僅差の場合に結論が反転しうる大きさ**である。静的なキー・バリュー47件であり実装コストは一度きりのため、初期実装に含めること。

> **【重要：都道府県の入力は1つに集約する】**
>
> 厳密には、以下のとおり参照すべき都道府県が異なる。
>
> | 用途 | 本来参照すべき都道府県 |
> |---|---|
> | 協会けんぽの健康保険料率 | **勤務先事業所の所在地**（＝加入している支部） |
> | 国民健康保険料 | **本人の住所地**（市区町村） |
>
> しかし2項目を入力させることはEFOの観点で許容できず、かつ**地域差の影響は国保のほうが桁違いに大きい**。したがって入力は「**お住まいの都道府県**」1つに集約し、健康保険料率にも同じ値を用いる。
>
> そのうえで、健康保険料の内訳表示の近傍に以下の注記を必ず表示すること。
>
> > ※協会けんぽの保険料率は、お勤め先の事業所がある都道府県によって決まります。お住まいの地域とお勤め先が別の都道府県の場合、実際の金額とは差が出ます。正確な料率は保険証またはお勤め先の労務担当者にご確認ください。

> **【実装注意】** 上記は仕様上の構造定義である。実装時は必ず**協会けんぽ公式サイトの当該年度の保険料額表**を一次情報として転記すること。また画面フッターに「料率適用年度：令和8年度」を表示し、ユーザーが情報の鮮度を判断できるようにすること。

## 4. 入力データ仕様（Input）— 段階的開示への全面再設計

> **【v17.0 最重要のUX変更】**
> v16.0は入力項目が最大20項目に達しており、「入力1分」という本ツール最大の価値提案と矛盾していた。特にSTEP 1で「直近5年の自己都合退職回数」「教育訓練の受講予定」という答えにくい質問を、まだ何のメリットも見ていないユーザーに課していた点は、離脱率の観点で致命的である。
>
> **v17.0では「コア4問で暫定結果を出し、精度を上げたい人だけ追加入力する」段階的開示（Progressive Disclosure）に再設計する。**

### 4.1 フェーズ1：コア入力（必須4項目）

**この4項目のみで、暫定の試算結果とToDoタイムラインを表示する。**

| 項目 | ID | UI要素 | 制約・補助機能 | 用途 |
|---|---|---|---|---|
| 退職を希望する日 | `inputResignDate` | `date` + クイックチップ | 過去日不可。「2週間後」「今月末」「来月末」ボタン | 全計算の起点 |
| 現在の有給残日数 | `inputPaidLeave` | `number` + チップ | 0〜60。「おまかせ（10日）」「フル消化（20日）」 | 有休消化逆算 |
| 去年1年間の年収 | `inputAnnualIncome` | `select`（14区分） | 「概算でOK」注記 | 標準報酬月額推定・住民税推定 |
| 退職後の進路 | `branchSelector` | 3択ボタン | ①転職／②療養・無職／③独立 | 進路別アドバイス切替 |

### 4.2 フェーズ2：精度向上入力（結果画面からの追加入力）

暫定結果カード上に配置したボタンから開くモーダルで入力させる。**「あと2問で、あなたの失業給付がいつから始まるか計算できます」**のように、追加入力の見返りを明示すること。

| 直近5年の自己都合退職回数 | `inputResignCount5Years` | `select` | 2回以下／3回以上 | 給付制限1ヶ月 vs 3ヶ月の判定 |

## 5. 計算アルゴリズム & エンジン仕様

### ① 【最重要修正】社会保険料の退職日別比較エンジン (`compareSocialInsuranceByResignDate`)

> **🔴 v16.0の重大な誤りと、その修正内容**
>
> v16.0の `calculateSocialInsuranceSavings()` は「退職日を月末に設定することで、当月分の社会保険料が**免除**されます」と出力する仕様だったが、**これは事実と正反対である。**
>
> **正しい制度の理解：**
>
> | 退職パターン | 資格喪失日 | 当月分の健保・厚年保険料 |
> |---|---|---|
> | **月末退職**（例：3/31） | 4/1（翌月1日） | **発生する**（労使折半）。退職月の給与から前月分＋当月分の2ヶ月分が控除されるのが一般的 |
> | **月末前退職**（例：3/30） | 3/31（当月中） | **発生しない**（資格喪失月の保険料は徴収されない） |
>
> つまり月末退職は「保険料が免除される」のではなく「**保険料は発生するが、会社が半分負担してくれる**」のである。
>
> 一方、月末前に退職すると健保・厚年の保険料は徴収されないが、**その月は国民健康保険＋国民年金（または任意継続・扶養）に自己負担100%で加入する**ことになる。
>
> **したがって「どちらが得か」は、以下の2つの実額を比較して初めて判定できる。**
>
> ```
> パターンA（月末退職）  : 健保本人負担 + 厚年本人負担 + (該当者のみ)介護保険本人負担
> パターンB（月末前退職）: 国民年金保険料(定額) + 国民健康保険料(前年所得ベース)
>                        ※任意継続を選ぶ場合は、任意継続保険料(全額自己負担)
>                        ※家族の扶養に入る場合は 0円
> ```
>
> v16.0のロジックのまま実装すると、**ユーザーが「得をする」と信じて選択した退職日で、実際には損をする可能性がある。** 免責事項があっても、集客資産としての信頼性を根本から毀損するため、本項目は最優先で修正すること。

> **【v17.1 設計方針：点推定を行わず、レンジ推定と3値判定を採用する】**
>
> 国民健康保険料は「医療分＋後期高齢者支援金分＋介護分（40〜64歳）」の3階建てで、それぞれに所得割と均等割があり、自治体によってはさらに平等割が加わる。料率・均等割額は市区町村ごとに設定されるため、**都道府県レベルの情報から単一の金額を正確に算出することは原理的に不可能である。**
>
> 単一の金額を表示すると、その精度が実態以上に信用される。これは「断定を避け、一次窓口への確認を促す」という本仕様書全体の原則（第6章）に反する。
>
> したがって **国保料はレンジ（幅）で推定し、両パターンのレンジが重なる場合は判定を保留（`UNCERTAIN`）する。**

```javascript
/**
 * 月末退職と月末前退職の自己負担額をレンジで比較する
 * @returns {{
 *   verdict: 'MONTH_END' | 'BEFORE_MONTH_END' | 'UNCERTAIN',
 *   patternA: number,
 *   patternB: { min: number, max: number },
 *   difference: { min: number, max: number },
 *   reductionApplied: boolean,
 *   breakdown: object
 * }}
 */
function compareSocialInsuranceByResignDate(input) {
  const { annualIncome, prefecture, age, afterInsurance, retireReason,
          isMentalPhysicalUnfit } = input;
  const standardWage = estimateStandardMonthlyWage(annualIncome);
  const isNursingCareTarget = (age >= 40 && age < 65);

  // ---- パターンA：月末退職（在職中の社会保険を1ヶ月分多く負担・確定値）----
  const healthRate = PREFECTURE_HEALTH_RATES[prefecture]
                  ?? RATE_MASTER.health.nationalAverageTotal;
  const employeeHealth  = Math.round(standardWage * healthRate / 2);
  const employeePension = Math.round(standardWage * RATE_MASTER.pension.employeeRate);
  const employeeNursing = isNursingCareTarget
    ? Math.round(standardWage * RATE_MASTER.nursingCare.employeeRate)
    : 0;
  const patternA = employeeHealth + employeePension + employeeNursing;

  // ---- パターンB：月末前退職（その月は自分で国保・国民年金等に加入・レンジ値）----
  let patternB = { min: 0, max: 0 };
  let reductionApplied = false;

  switch (afterInsurance) {
    case 'kokuho': {
      // 非自発的失業者の軽減措置の判定（v17.1新設）
      reductionApplied = judgeInvoluntaryReduction({ retireReason, isMentalPhysicalUnfit, age });
      const nhi = estimateNationalHealthInsurance({
        annualIncome, age, applyReduction: reductionApplied,
      });
      patternB = {
        min: RATE_MASTER.nationalPension.monthlyPremium + nhi.min,
        max: RATE_MASTER.nationalPension.monthlyPremium + nhi.max,
      };
      break;
    }
    case 'nini_keizoku': {
      // 任意継続は労使折半がなくなり全額自己負担（保険者ごとに上限あり）
      // 保険料は確定的に算出できるためレンジ幅を持たせない
      const nini = Math.round(standardWage * healthRate)
                 + (isNursingCareTarget ? Math.round(standardWage * RATE_MASTER.nursingCare.totalRate) : 0);
      const total = RATE_MASTER.nationalPension.monthlyPremium + nini;
      patternB = { min: total, max: total };
      break;
    }
    case 'fuyou': {
      // 家族の健康保険の扶養に入る場合、健康保険料の自己負担なし
      // 配偶者の扶養で国民年金第3号に該当する場合は年金保険料も0円
      const pension = isThirdCategoryEligible(input)
        ? 0
        : RATE_MASTER.nationalPension.monthlyPremium;
      patternB = { min: pension, max: pension };
      break;
    }
  }

  // ---- 判定（3値）----
  const diffMin = patternB.min - patternA;
  const diffMax = patternB.max - patternA;

  let verdict;
  if (diffMin > 0 && diffMax > 0)       verdict = 'MONTH_END';        // 常に月末が安い
  else if (diffMin < 0 && diffMax < 0)  verdict = 'BEFORE_MONTH_END'; // 常に月末前が安い
  else                                  verdict = 'UNCERTAIN';        // レンジが跨ぐ＝判定不能

  return {
    verdict,
    patternA,
    patternB,
    difference: { min: Math.abs(diffMin), max: Math.abs(diffMax) },
    reductionApplied,
    breakdown: { employeeHealth, employeePension, employeeNursing },
  };
}
```

#### ①-b 国民健康保険料のレンジ推定 (`estimateNationalHealthInsurance`)

```javascript
function estimateNationalHealthInsurance({ annualIncome, age, applyReduction }) {
  const C = RATE_MASTER.nationalHealthInsurance;
  const isNursing = (age >= 40 && age < 65);

  // 給与収入 → 給与所得（給与所得控除後）
  let salaryIncome = calcSalaryIncomeAfterDeduction(annualIncome);

  // 非自発的失業者の軽減：給与所得を100分の30とみなす
  if (applyReduction) {
    salaryIncome = Math.round(salaryIncome * RATE_MASTER.involuntaryUnemploymentReduction.incomeMultiplier);
  }

  // 賦課基準額 ＝ 給与所得 − 基礎控除
  const base = Math.max(0, salaryIncome - C.basicDeduction);

  const incomeMin = base * (C.incomeRateMin + (isNursing ? C.nursingIncomeRateMin : 0));
  const incomeMax = base * (C.incomeRateMax + (isNursing ? C.nursingIncomeRateMax : 0));
  const perCapitaMin = C.perCapitaMin + (isNursing ? C.nursingPerCapitaMin : 0);
  const perCapitaMax = C.perCapitaMax + (isNursing ? C.nursingPerCapitaMax : 0);

  // 年額 → 月額換算
  return {
    min: Math.round((incomeMin + perCapitaMin) / 12),
    max: Math.round((incomeMax + perCapitaMax) / 12),
  };
}
```

#### ①-c 非自発的失業者の国保軽減措置の判定 (`judgeInvoluntaryReduction`) — v17.1新設

> **【新設の理由】** 本措置は月末／月末前の判定を**反転させうる最重要ファクター**である。これを織り込まないと、会社都合離職者や体調不良で退職する方（＝最も経済的支援が必要な層）に対して、逆の推奨を出すおそれがある。

雇用保険の**特定受給資格者**（倒産・解雇等）および**特定理由離職者**（雇止め、体調不良による正当な理由のある自己都合等）に該当し、**離職時に65歳未満**である場合、市区町村への申請により**前年の給与所得を100分の30とみなして**国民健康保険料が算定される。

- **軽減期間**: 離職日の翌日が属する月から、その月が属する年度の翌年度末まで
- **対象所得**: 本人の**給与所得のみ**。営業所得・不動産所得等は軽減対象外
- **申請主義**: 自動適用されない。雇用保険受給資格者証等を持参して市区町村窓口での届出が必要

```javascript
function judgeInvoluntaryReduction({ retireReason, isMentalPhysicalUnfit, age }) {
  if (age >= RATE_MASTER.involuntaryUnemploymentReduction.maxAge) return false;

  // 特定受給資格者：会社都合
  if (retireReason === 'company') return true;
  // 特定理由離職者：契約期間満了（雇止め）
  if (retireReason === 'contract_end') return true;
  // 特定理由離職者：体調不良等による正当な理由のある自己都合
  if (retireReason === 'personal' && isMentalPhysicalUnfit === 'yes') return true;

  return false;
}
```

**⚠️ 表示上の必須要件**: 本措置が適用される可能性がある場合、**必ず申請が必要である旨をToDoタイムラインのタスクとして表示すること**。自動適用と誤解されると、ユーザーは受けられたはずの軽減を逃す。

> **【申請のお知らせ】** 会社都合または体調不良でのご退職の場合、国民健康保険料が大きく軽減される制度があります（前年の給与所得を30%とみなして計算）。**この制度は自動では適用されません。** ハローワークで受け取る雇用保険受給資格者証をお持ちのうえ、お住まいの市区町村の国民健康保険の窓口でお手続きください。

#### 出力文言のルール（厳守）

- **「免除」という語は一切使用しない。**
- 必ず両パターンの金額を並べて提示し、内訳を開示する。
- 国保が絡むパターンBは**必ずレンジで表示**する。点推定の金額を単独で出してはならない。
- `verdict` の3値それぞれに対応する文言を用意する。

**表示例① `verdict: 'MONTH_END'`（月末退職が有利）**

> **月末（3月31日）に退職した場合**
> 3月分の社会保険料 **20,150円**
> （内訳：健康保険 7,380円 ／ 厚生年金 12,770円）※会社が同額を負担しています
>
> **3月30日に退職した場合**
> 国民年金 17,920円 ＋ 国民健康保険 **約16,000〜21,000円**
> ＝ 合計 **約33,900〜38,900円**
>
> → この条件では、**月末退職のほうが約13,700〜18,700円おトク**になる見込みです。

**表示例② `verdict: 'UNCERTAIN'`（判定保留）**

> この条件では、**どちらが有利かは判定が分かれます。**
>
> 月末退職：**20,150円**
> 月末前退職：**約18,000〜23,000円**
>
> 国民健康保険料はお住まいの市区町村によって幅があるため、この条件では逆転する可能性があります。
> お住まいの自治体のウェブサイトに保険料の試算ページが用意されていることが多いので、そちらでご確認いただくと正確です。

**表示例③ `reductionApplied: true`（軽減措置が適用されうる場合）**

> 会社都合でのご退職のため、**国民健康保険料の軽減措置**（前年の給与所得を30%とみなして計算）を適用した金額で試算しています。
> **この軽減は自動では適用されません。**市区町村の窓口でのお手続きが必要です。

**全パターン共通の注記（必須）**

> ※国民健康保険料は前年の所得とお住まいの市区町村により大きく変動します。上記は全国的な料率の幅から算出した目安です。正確な額はお住まいの市区町村へご確認ください。

### ② 【新設】住民税の退職月別徴収ロジック (`calculateResidentTaxImpact`)

> **【v17.0新設の理由】** v16.0は「手取り損益額を円表示で算出する」と謳いながら、**退職月によって最も金額が動く住民税を計算に含めていなかった。** 1〜4月退職では最終給与から残額が一括徴収され、数十万円が引かれるケースがある。社会保険料の差額（数万円規模）よりインパクトが大きいため、本項目なしに「手取り最大化」を名乗ることはできない。

住民税は前年所得に対して課税され、**6月〜翌年5月**の12回に分けて給与から特別徴収される。退職月により以下の扱いとなる。

| 退職月 | 扱い |
|---|---|
| **1月〜4月** | **残額（退職月〜5月分）を最終給与等から一括徴収**（地方税法上、原則として事業主に義務あり） |
| **5月** | その月分のみ通常どおり徴収 |
| **6月〜12月** | 原則として**普通徴収**（自宅に納付書が届き自分で納付）。本人が申し出れば一括徴収も可能 |

```javascript
function calculateResidentTaxImpact(resignDate, annualIncome) {
  const month = resignDate.getMonth() + 1;
  const annualResidentTax = estimateAnnualResidentTax(annualIncome);
  const monthlyAmount = Math.round(annualResidentTax / 12);

  if (month >= 1 && month <= 4) {
    // 退職月から5月までの残り月数を一括徴収
    const remainingMonths = 5 - month + 1;
    return {
      type: 'LUMP_SUM_MANDATORY',
      amount: monthlyAmount * remainingMonths,
      months: remainingMonths,
      message: `${month}月退職の場合、${month}月分から5月分までの住民税 約${(monthlyAmount * remainingMonths).toLocaleString()}円が最終給与などから一括で差し引かれます。最後の手取りが大きく減る可能性があるため、生活費の準備にご注意ください。`,
    };
  }
  if (month === 5) {
    return { type: 'NORMAL', amount: monthlyAmount, message: '5月退職の場合、住民税は通常どおり1ヶ月分の徴収で完了します。' };
  }
  // 6月〜12月
  return {
    type: 'ORDINARY_COLLECTION',
    amount: monthlyAmount * (12 - month + 5),
    message: `${month}月退職の場合、残りの住民税は原則としてご自宅に届く納付書でご自分で納めます（普通徴収）。給与天引きがなくなるぶん、後から請求が来る点にご注意ください。`,
  };
}
```

> **【表示上の注意】** 住民税は「退職日を変えれば減る」性質のものではなく、**支払うタイミングが変わるだけ**である。「損」として計上せず、**「キャッシュフロー上の注意」**として別枠で提示すること。総損得額に合算すると実態と乖離する。

### ③ 雇用保険法改正対応：給付制限期間動的判定 (`calculateUnemploymentRestriction`)

2025年4月1日以降の退職について、給付制限期間は原則2ヶ月から1ヶ月に短縮された。ただし5年以内に3回以上自己都合退職している場合は3ヶ月、教育訓練を受講した場合は制限解除となる。

function calculateUnemploymentRestriction(input) {

  if (age >= 65) {

      restrictionMonths: 0,
      code: 'HIGH_AGE_LUMP_SUM',
      text: '高年齢求職者給付金（一時金）の対象',

    };
  }

  // ---- v17.0新設：会社都合・定年退職の分岐 ----
  if (retireReason === 'company') {
    return { restrictionMonths: 0, code: 'COMPANY_REASON', text: '給付制限なし（会社都合）' };
  }
  if (retireReason === 'retirement_age') {
    return {
      restrictionMonths: 0,
      code: 'MANDATORY_RETIREMENT',
      text: '給付制限なし（定年退職）',
      note: '定年退職は給付制限の対象外です。ただし「特定受給資格者」ではないため、所定給付日数は一般の受給資格者と同じ扱いになります。',
    };
  }
  if (retireReason === 'contract_end') {
    return { restrictionMonths: 0, code: 'CONTRACT_END', text: '給付制限なし（契約期間満了）' };
  }

  // ---- 自己都合 ----
  if (targetDate < enforcementDate) {
    return { restrictionMonths: 2, code: 'OLD_RULE_2M', text: '給付制限 2ヶ月（2025年3月までの旧ルール）' };

  if (isEnrolledEducation === 'yes') {

    };
  }
  if (resignCount5Years === '3_or_more') {
    return {
      restrictionMonths: 3,
      code: 'FREQUENT_RESIGN_3M',
      text: '給付制限 3ヶ月（5年以内に3回以上）',
      note: '過去5年以内に自己都合退職による受給手続きを3回以上行っている場合、3回目以降は3ヶ月の給付制限となります。',
    };
  }
  return { restrictionMonths: 1, code: 'NEW_RULE_2025_1M', text: '給付制限 1ヶ月（2025年4月改正）' };
}

### ④ 【修正】傷病手当金の受給要件判定 (`judgeSicknessAllowanceEligibility`)

> **🔴 v16.0の欠落と修正内容**
>
> v16.0は「退職日に出勤すると受給権が永久消滅する」という警告のみを実装していたが、**資格喪失後の継続給付には、その前提となる受給要件が存在する**ことが完全に抜けていた。
>
> **健康保険法第104条（傷病手当金又は出産手当金の継続給付）の要件：**
> 1. **資格喪失日の前日まで、継続して1年以上の被保険者期間があること**
> 2. **資格喪失の際に、現に傷病手当金の支給を受けているか、受給できる状態にあること**
>
> v16.0には**在籍年数の入力項目が存在しなかった**ため、そもそも判定が不可能だった。在職1年未満の人には継続給付自体が存在しないにもかかわらず「退職日に出勤するな」と警告することになり、逆に該当者には要件充足の確認機会を与えられていなかった。
>
> また「**永久消滅**」という表現は不正確である。正しくは「継続給付の要件を満たさなくなる」であり、**在職中の傷病手当金は別途請求可能**である。

```javascript
function judgeSicknessAllowanceEligibility(input) {
  const { tenureYears, isMentalPhysicalUnfit, insuranceType } = input;

  if (isMentalPhysicalUnfit !== 'yes') {
    return { applicable: false };
  }

  // 要件①：継続1年以上の被保険者期間
  if (tenureYears < 1) {
    return {
      applicable: false,
      code: 'TENURE_UNDER_1Y',
      level: 'info',
      message: '在籍期間が1年未満のため、退職後に傷病手当金を継続して受け取る制度（資格喪失後の継続給付）の対象外となる可能性が高いです。ただし在職中の傷病手当金は別途請求できます。詳しくはご加入の健康保険の窓口へご確認ください。',
    };
  }

  return {
    applicable: true,
    code: 'CONTINUATION_POSSIBLE',
    level: 'caution',
    requirements: [
      '退職日の前日まで、継続して1年以上健康保険に加入していること',
      '退職日の時点で、傷病手当金を受けているか、受けられる状態（労務不能）であること',
      '退職日に労務不能の状態であること（＝出勤しないこと）',
    ],
    // ⚠️ 表現ガイドラインは第6章を参照
    message: '退職日に出勤して業務を行うと「働ける状態だった」と判断され、退職後の継続給付を受けられなくなる場合があります。退職日は出勤せず、有給休暇の取得または欠勤として扱うことをご検討ください。ご自身のケースについては、必ず事前にご加入の健康保険の窓口へご確認ください。',
  };
}
```

### ⑤ 「特定理由離職者」判定ロジック

`retireReason === 'personal'` かつ `isMentalPhysicalUnfit === 'yes'` の場合、ハローワークでの「特定理由離職者」認定について案内する。

- **特例効果**: 給付制限が解除され、受給要件が「離職前2年間に被保険者期間12ヶ月」から「離職前1年間に6ヶ月」へ緩和される。また国民健康保険料の軽減措置の対象となる場合がある。
- **⚠️ 表現の注意**: 認定を行うのは**ハローワークであり本ツールではない**。「認定されます」と断定せず、「**認定される可能性があります。医師の診断書等をお持ちのうえ、ハローワークにご相談ください**」と表現すること。

### ⑥ 退職所得の試算 (`calculateRetirementIncomeTax`)

```javascript
function calculateRetirementIncomeTax(retirementPay, tenureYears, hasSubmittedForm) {
  // 勤続年数は1年未満切り上げ
  const years = Math.ceil(tenureYears);

  const deduction = years <= 20
    ? Math.max(RATE_MASTER.retirementIncome.deductionPerYearUnder20 * years,
               RATE_MASTER.retirementIncome.minimumDeduction)
    : 8000000 + RATE_MASTER.retirementIncome.deductionPerYearOver20 * (years - 20);

  if (!hasSubmittedForm) {
    return {
      withholding: Math.round(retirementPay * RATE_MASTER.retirementIncome.withholdingRateWithoutForm),
      // ⚠️ v17.0追記：確定申告で取り戻せる旨を必ず併記すること
      note: '「退職所得の受給に関する申告書」を提出しないと、退職金の全額に20.42%が源泉徴収されます。ただし、その場合でも翌年の確定申告により納めすぎた分の還付を受けられます。提出し忘れても取り返しがつかないわけではありません。',
    };
  }

  const taxableIncome = Math.max(0, (retirementPay - deduction) / 2);
  return { deduction, taxableIncome, note: '退職所得控除により、多くの場合で税負担は大きく軽減されます。' };
}
```

### ⑦ 再就職手当と開業日の関係（進路③独立）

自己都合退職で給付制限がある場合、開業のタイミングには注意が必要である。

- 待期期間（7日）中の開業は、そもそも失業状態と認められない
- **給付制限期間中に自ら事業を開始した場合、再就職手当の対象とならない**（給付制限期間中の再就職手当は、ハローワーク等の紹介による就職に限られるため、自営業は対象外）
- したがって再就職手当を受けたい場合、**待期7日＋給付制限期間の経過後**に開業届を提出するのが原則となる

```javascript
function calculateRecommendedOpeningDate(resignDate, restriction) {
  const waitingEnd = addDaysSafe(resignDate, RATE_MASTER.employmentInsurance.waitingPeriodDays);
  // ※実際の待期起算日は「受給資格決定日」であり離職日ではない点に注意
  const restrictionEnd = addMonthsSafe(waitingEnd, restriction.restrictionMonths);
  return {
    earliestSafeDate: restrictionEnd,
    note: '再就職手当を受け取りたい場合、給付制限期間が終わってから開業届を出すことが原則です。なお、待期期間はハローワークで求職の申し込みをした日から数えるため、実際の日付は手続き日によって変わります。',
  };
}
```

> **⚠️ 実装注意**: 待期7日の起算日は「離職日」ではなく「ハローワークで求職申込みを行った日（受給資格決定日）」である。本ツールは離職日しか知り得ないため、**算出結果はあくまで「ハローワークに◯月◯日に行った場合の目安」として表示**し、断定を避けること。

### ⑧ 2026年10月施行 社会保険適用拡大（参考情報として提供）

> **【v17.0でのスコープ変更】** v16.0はこれを「計算アルゴリズム」の章に置いていたが、これは**短時間労働者が社会保険に加入する側**の制度改正であり、退職日を最適化するという本ツールの主目的とは接点が薄い。実装者の混乱を避けるため、**参考情報セクションへ移動する。**

2026年10月から、短時間労働者の社会保険加入要件のうち「月額賃金8.8万円以上（年収約106万円）」という賃金要件が撤廃される。企業規模要件についても2027年10月から段階的に撤廃され、2035年10月に全企業が対象となる予定である。

**本ツールでの扱い**: 退職後に扶養内でパート勤務を検討しているユーザー向けの補足情報として、進路「②療養・無職」選択時のアコーディオン内に表示する。計算ロジックには組み込まない。

## 6. 警告・注意表示の設計ガイドライン（v17.0新設）

> **【新設の理由】** 本ツールは「体調不調・メンタル不調あり」と申告したユーザーに対して警告を表示する設計になっている。**判断力が低下している可能性のある人に対して、不安を煽る表現は有害に作用しうる。** v16.0には「永久消滅」「激減」「絶対に」といった強い表現が多用されており、かつ相談窓口への導線が一つもなかった。

### 6.1 表現の原則

| 禁止表現 | 推奨表現 |
|---|---|
| 永久に消滅します | 受けられなくなる場合があります |
| 手取りが激減します | 手取りが大きく減る可能性があります |
| 絶対に〜してはいけません | 〜されないことをおすすめします |
| 必ず損をします | 〜のほうが有利になるケースが多いです |
| 認定されます | 認定される可能性があります |

**原則**: 断定を避け、「可能性」で語る。そのうえで**必ず一次窓口（健保組合・ハローワーク・年金事務所・主治医）への確認を促す**。

### 6.2 体調不調フラグ時の必須表示

`isMentalPhysicalUnfit === 'yes'` の場合、警告カードの直後に以下を**必ず**表示する。

```html
<div class="support-box" role="complementary">
  <p><strong>一人で判断しなくて大丈夫です。</strong></p>
  <p>体調やお仕事のことで迷われているときは、以下の窓口にご相談いただけます。</p>
  <ul>
    <li>主治医・産業医（傷病手当金の申請には医師の意見が必要です）</li>
    <li>加入中の健康保険組合／協会けんぽ の窓口</li>

</div>
```

警告の重要度を色のみで表現してはならない。**アイコン＋テキストラベル＋色**の3要素で区別すること（色覚多様性への配慮）。

| 給付制限 | 雇用保険法 第33条 ✅ | **雇用保険法 第33条**（正しい） |

**補足**：
- 健康保険法**第102条は出産手当金**の規定であり、傷病手当金とは別制度である
- 健康保険法**第126条は日雇特例被保険者**に関する規定であり、本ツールの対象範囲外である
- 傷病手当金の支給期間（通算1年6ヶ月）は健康保険法**第99条第4項**

**実装要件**: `schema_generator.js` の `Legislation` スキーマ生成時、および画面上の法令表示時に、上記の正しい条文番号と e-Gov 法令検索の該当URLをセットで出力すること。

## 13. ユーザーフィードバック機能仕様（v17.2新設）

> **【新設の理由】** 本ツールは法令に基づく金額を提示するが、**実際の金額が正しかったかを知る手段が運営者側に一切ない。** ユーザーが年金事務所や市区町村で確認して「実際は違った」と気づいても、その情報が運営者に戻ってこなければ精度は永久に上がらない。
>
> β版の目的は「①法令試算エンジンの精度検証 ③ユーザーの実際の悩み・離脱ポイントの把握」（第0章）であり、**フィードバック機能なしにこの目的は達成できない。**

### 13.1 「外部依存ゼロ」制約に対する例外の定義

第2章で定義した「外部依存**完全ゼロ**・サーバ通信なし」に対し、**フィードバック送信のみを明示的な例外**とする。ただし以下の条件を厳守する。

| 条件 | 内容 |
|---|---|
| **送信は完全な能動操作に限る** | ユーザーがボタンをタップした瞬間にのみ発生。自動送信・バックグラウンド送信は一切行わない |
| **試算そのものは従来どおり通信ゼロ** | 計算処理でネットワークを使わない設計は維持する |
| **外部スクリプトは読み込まない** | 第三者製の埋め込みフォーム（Formspree、Tally等）のJSタグは使用しない |
| **Cookieを使用しない** | トラッキング目的の識別子を発行しない |
| **要配慮情報は送信しない** | 詳細は 13.4 |

### 13.2 実装フェーズ

#### Phase 1（β版初期・実装コスト最小）: Googleフォーム＋URLパラメータ事前入力

外部リンクとして開くだけなので、**サイト側にスクリプトを読み込まず「外部依存ゼロ」の実質を維持できる。**

```javascript
function buildFeedbackUrl(category) {
  const base = 'https://docs.google.com/forms/d/e/{FORM_ID}/viewform';
  const params = new URLSearchParams({
    'usp': 'pp_url',
    'entry.{CATEGORY_FIELD}': category,          // 報告の種類
    'entry.{CONTEXT_FIELD}': buildContextSummary(), // 条件サマリ（13.3）
  });
  return `${base}?${params}`;
}
```

- 実装時間の目安：1〜2時間
- 制約：👍（肯定）のカウントが取得できない（13.5で後述）

#### Phase 2（フィードバック件数が週5件を超えたら）: Cloudflare Pages Functions ＋ KV

すでにCloudflare Pages上で稼働しているため、**同一ドメインのファーストパーティ通信**として実装できる。外部サービスへのデータ送信が発生しない点で、Phase 1よりプライバシー上も優れる。

```javascript
// functions/api/feedback.js
export async function onRequestPost(context) {
  const { request, env } = context;
  const body = await request.json();

  // レート制限（同一IPから1時間10件まで）※IPは保存せずハッシュのみ
  // バリデーション（自由記述 1000文字以内、要配慮キー混入チェック）

  const id = crypto.randomUUID();
  await env.FEEDBACK_KV.put(`fb:${Date.now()}:${id}`, JSON.stringify(body), {
    expirationTtl: 60 * 60 * 24 * 365, // 1年
  });
  return new Response(JSON.stringify({ ok: true }), { status: 200 });
}
```

### 13.3 送信ペイロード仕様

> **【設計の核心】** 「計算が間違っている」という報告は、**入力条件が分からなければ再現も修正もできない。** フィードバックの価値の大半は、この条件サマリが自動で付くかどうかで決まる。

```javascript
function buildContextSummary() {
  return [
    `V:${SPEC_VERSION}`,              // 仕様バージョン（例: v17.2）
    `RY:${RATE_MASTER.fiscalYear}`,   // 適用料率年度
    `RD:${state.resignDate}`,         // 退職希望日
    `PF:${state.prefecture}`,         // 都道府県
    `IN:${state.annualIncomeCategory}`, // 年収区分（区分名のみ・実額は送らない）
    `AG:${toAgeDecade(state.age)}`,   // 年代（40代等。生年月日は送らない）
    `TN:${state.tenureYears}`,        // 在籍年数
    `BR:${state.branch}`,             // 進路
    `RR:${state.retireReason}`,       // 退職区分
    `AI:${state.afterInsurance}`,     // 退職後の健康保険
    `VD:${state.result.verdict}`,     // 判定結果（MONTH_END等）
    `RA:${state.result.reductionApplied}`, // 軽減措置の適用有無
  ].join('|');
}
```

**出力例**
```
V:v17.2|RY:令和8年度|RD:2026-09-30|PF:大阪府|IN:400-450|AG:40s|TN:5|BR:transfer|RR:personal|AI:kokuho|VD:MONTH_END|RA:false
```

#### 送信前の透明性表示（必須）

送信ボタンの直上に、**実際に送られる文字列をそのまま表示する。**

> **一緒に送られる情報**
> `V:v17.2|RY:令和8年度|RD:2026-09-30|PF:大阪府|...`
>
> ※お名前・メールアドレス・生年月日・勤務先などは含まれません。ご自由記入欄には個人が特定される情報を書かないようお願いします。

### 13.4 送信してはならない情報（厳守）

| 項目 | 理由 |
|---|---|
| **`inputMentalPhysicalUnfit`（体調不調フラグ）** | 要配慮個人情報に相当。第10章で保存も禁止しており、送信も当然禁止 |
| 生年月日・年齢の実値 | 年代（`40s`）に丸めて送信する |
| 年収の実額 | 区分名（`400-450`）のみ |
| 退職金額・ボーナス額の実額 | 送信しない |
| IPアドレス・UA文字列の生値 | Phase 2ではハッシュ化のうえレート制限にのみ使用し、保存しない |
| Cookie・永続的な識別子 | 発行しない |

```javascript

const FORBIDDEN_KEYS = ['inputMentalPhysicalUnfit', 'birthDate', 'retirementPayAmount', 'bonusAmount'];
function assertNoSensitiveData(payload) {
  const json = JSON.stringify(payload);
  FORBIDDEN_KEYS.forEach(k => {
    if (json.includes(k)) throw new Error(`要配慮情報が含まれています: ${k}`);
  });
}
```

### 13.5 フィードバックの3つの入口

#### 入口A：結果画面のマイクロフィードバック（最重要）

**タップ後の挙動**

| 選択 | Phase 1の挙動 | Phase 2の挙動 |

## 14. FAQ仕様（v17.2新設）

> **【設計方針】** FAQは「ページ下部に置く質問リスト」ではない。本ツールにおけるFAQの役割は次の3つである。
>
> 1. **知識のアップデート**：ユーザーが持っている誤解（特に「月末退職なら保険料が免除される」等）を正す
> 2. **行動への接続**：知って終わりにせず、「いつ・どこで・何を持って」まで示す
> 3. **AI検索での引用獲得**：第1章で再定義したとおり、Googleのリッチリザルト目的ではなくLLM引用目的

### 14.1 FAQの3層構造

| 層 | 配置 | 内容 | 目的 |
|---|---|---|---|
| **第1層：文脈連動FAQ** | 結果画面のタイムライン直下 | **その人の条件に該当する3〜5件のみ**を自動抽出 | 行動接続 |
| **第2層：全件FAQ** | `/faq` 相当のアコーディオン | 全項目をカテゴリ分類して掲載 | SEO / AIO |
| **第3層：用語ミニ解説** | 本文中の専門用語 | タップで小さなポップオーバー | 読解の補助 |

### 14.2 FAQ項目の必須構造（テンプレート固定）

**すべてのFAQ項目は以下の4要素を必ず持つ。行動（A-3）を書けない項目は掲載しない。**

```
Q  : 質問（ユーザーが使う言葉で書く。専門用語で始めない）
A-1: 結論（30〜50字・太字）  ← Snippet Fuel。AI引用の対象
A-2: 理由・補足（2〜4文）
A-3: → 次にやること（時期・窓口・持ち物を具体的に）
     [この説明は分かりやすかったですか？ 👍 🤔]
```

#### 記述例

> **Q. 月末に辞めたほうが得って聞いたけど本当ですか？**
>
> **A. 条件によって変わります。月末退職で保険料が「免除」されるわけではありません。**
>
> 月末に退職すると、その月の社会保険料は発生しますが、会社が半分を負担してくれます。一方、月末より前に退職すると、その月の健康保険・厚生年金の保険料は引かれませんが、代わりに国民健康保険と国民年金に自分で全額を払うことになります。どちらが安いかは、年収・お住まいの市区町村・扶養に入れるかどうかで変わります。
>
> **→ 次にやること**
> 上の試算結果で「判定が分かれます」と表示された方は、お住まいの市区町村のウェブサイトにある国民健康保険料の試算ページで確認してみてください。「（市区町村名） 国民健康保険料 試算」で検索すると見つかります。

### 14.4 第1層（文脈連動FAQ）の抽出ロジック

```javascript
function selectContextualFaqs(state, result) {
  const matched = FAQ_MASTER.filter(faq => evaluateTrigger(faq.trigger, state, result));

  // 優先度：①誤解を正すもの ②金額インパクトが大きいもの ③期限があるもの
  const sorted = matched.sort((a, b) => b.priority - a.priority);

  // 表示は最大5件。多すぎると読まれない
  return sorted.slice(0, 5);
}
```

**表示件数の上限は5件とする。** 全件を結果画面に並べると読まれず、行動接続という目的を果たさない。残りは「よくある質問をすべて見る」リンクから第2層へ誘導する。

### 14.5 構造化データとの連動

第1章で定義したとおり、FAQPageスキーマの目的は**AI検索での引用獲得**である。

```javascript
// schema_generator.js
function generateFaqSchema(visibleFaqs) {
  // ⚠️ 画面に表示していないFAQをスキーマに含めてはならない
  //    （構造化データは可視コンテンツと一致している必要がある）
  return {
    '@context': 'https://schema.org',
    '@type': 'FAQPage',
    mainEntity: visibleFaqs.map(faq => ({
      '@type': 'Question',
      name: faq.question,
      acceptedAnswer: {
        '@type': 'Answer',
        // A-1（結論）＋A-2（理由）を含める。A-3（行動）まで入れると引用時に有用
        text: `${faq.conclusion} ${faq.detail} ${faq.action}`,
      },
    })),
  };
}
```

### 14.6 FAQ執筆ガイドライン

| 原則 | 内容 |
|---|---|
| **質問はユーザーの言葉で** | ❌「資格喪失日について」→ ⭕「保険証はいつまで使える？」 |
| **結論を最初に、30〜50字で** | AI検索の要約に引用されやすく、かつスマホで折り返さない長さ |
| **行動を必ず書く** | 「窓口の名前」「持ち物」「時期」の3点を含める |
| **断定を避ける** | 第6章の表現ガイドラインに従う（「〜の場合があります」） |
| **金額は幅で書く** | 点推定を避ける（第5章の方針と一貫させる） |
| **他責的に書かない** | 会社批判・制度批判のトーンを避ける。中立を保つことが士業連携時の資産になる |

```
ユーザーが FAQ末尾の「🤔 分かりにくい」をタップ
    ↓

    ↓

```

**この仕組みにより、FAQは「一度書いて終わり」ではなく、実際の読者の反応で磨かれるコンテンツ資産になる。** SEO・AIOの観点でも、更新され続けるFAQは静的なFAQより有利である。
