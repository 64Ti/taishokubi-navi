# 『トク退』フィードバックフォーム設計書 v1.0（Phase 1）

> 本ファイルは仕様書 v17.2 第13章で定義したユーザーフィードバック機能の、**Phase 1（Googleフォーム）における具体的な設計**である。
>
> | 項目 | 内容 |
> |---|---|
> | 作成日 | 2026年8月5日 |
> | 対象フェーズ | Phase 1（β版初期） |
> | 移行条件 | 週5件を超えたら Phase 2（Cloudflare Pages Functions）へ |
> | 実装工数の目安 | フォーム作成1時間＋サイト側の実装1時間 |

---

## 0. 設計の前提

### なぜGoogleフォームから始めるのか

| 理由 | 内容 |
|---|---|
| **外部スクリプトを読み込まない** | 埋め込みではなく**リンクで開く**方式のため、サイト側の「外部依存ゼロ」の実質が保たれる |
| **サーバ実装が不要** | β版の目的は「集めること」であり、まず回り始めることを優先する |
| **集計が即座にできる** | スプレッドシート連携で分析基盤が最初から手に入る |

### Phase 1の割り切り

- **👍（肯定）のカウントは取得できない。** タップ後に「ありがとうございます」を表示して終了する
- **フォームへ遷移するため離脱が発生する。** そのぶん、遷移する価値のある選択肢（🤔／😥）に絞る
- Phase 2で両方を計測できるようにする

---

## 1. Googleフォーム側の設定（必須項目）

フォーム作成後、以下の設定を**必ず**確認すること。設定を誤ると、個人情報の収集や回答障壁の発生につながる。

| 設定項目 | 設定値 | 理由 |
|---|---|---|
| **メールアドレスを収集する** | **オフ** | 仕様書13.8で収集しないと定めている |
| **回答者にログインを必須にする** | **オフ** | Googleアカウントを持たない方が回答できなくなる |
| **回答を1回に制限する** | **オフ** | ログイン必須になるため。重複はスプレッドシート側で判断 |
| **回答後に編集を許可** | オフ | 不要 |
| **概要グラフを表示** | オフ | 他人の回答が見えるのは不適切 |
| **進行状況バーを表示** | **オン** | 何問残っているかが分かると離脱が減る |
| **回答の通知メール** | **オン** | 週次レビューの取りこぼしを防ぐ |
| **スプレッドシート連携** | **オン** | 分析の基盤 |

## 2. フォーム構成（セクション分岐あり）

```
セクション1  導入＋カテゴリ選択
   ├─ 計算結果が実際と違った → セクション2A ★最重要
   ├─ 内容が間違っている・古い → セクション2B
   ├─ 使い方が分からなかった  → セクション2C
   ├─ こんな条件にも対応して   → セクション2D
   └─ 感想・応援              → セクション2E
                                   ↓（すべて）
                              セクション3 共通・送信
```

> **【Googleフォームの制約】** セクション分岐は「ラジオボタン」または「プルダウン」でのみ設定できる。カテゴリ選択は必ずラジオボタンにすること。

## 3. 各セクションの設計

### セクション1：導入＋カテゴリ選択

**セクションタイトル**
> ご意見をお聞かせください

**説明文**
> トク退をご利用いただきありがとうございます。
> いただいたご指摘は、計算内容の修正や説明の改善に使わせていただきます。修正した内容は、サイト内の「更新履歴」でご報告します。
>
> ⚠️ お名前・ご連絡先・お勤め先など、個人が特定される情報はご記入なさらないようお願いします。
> ※ このフォームではメールアドレスを収集していません。個別のご返信はできかねますことをご了承ください。

---

**Q1. どのようなご報告でしょうか？**（ラジオボタン・必須）

| 選択肢 | 分岐先 | 内部値 |
|---|---|---|
| 計算結果が、実際の金額と違っていた | セクション2A | `calc_mismatch` |
| 説明の内容が間違っている・古いと思う | セクション2B | `content_error` |
| 使い方が分からなかった | セクション2C | `usability` |
| こんな条件にも対応してほしい | セクション2D | `feature_request` |
| 感想・応援 | セクション2E | `praise` |

> **【設計意図】** 選択肢の順序は**運営者にとっての価値順**にしている。最上段に置くことで、最も欲しい「実額のズレ」の報告を集めやすくする。

### セクション2A：計算結果が実際と違った ★最重要

**セクションタイトル**
> 実際の金額を教えてください

**説明文**
> ここが、トク退をいちばん正確にできる情報です。差し支えない範囲で構いませんので、分かる項目だけご記入ください。

---

**Q2A-1. どの項目の金額が違っていましたか？**（ラジオボタン・必須）

- 社会保険料（健康保険・厚生年金）
- 国民健康保険料
- 国民年金保険料
- 住民税
- 退職金の税金
- 失業保険（基本手当）
- 傷病手当金
- その他

**Q2A-2. トク退が表示していた金額**（記述式・任意）
> 説明文：おおよそで構いません。数字のみをご記入ください（例：20150）

**Q2A-3. 実際の金額**（記述式・必須）
> 説明文：数字のみをご記入ください（例：18400）

**Q2A-4. その金額はどこで確認されましたか？**（ラジオボタン・必須）

- 年金事務所
- 市区町村の窓口（国民健康保険・住民税）
- ハローワーク
- 加入していた健康保険組合・協会けんぽ
- 勤務先の人事・労務
- 税務署
- 実際の通知書・納付書が届いた
- その他

> **【設計意図】** 確認元が分かると、**その情報の信頼度を重み付けできる。** 「通知書が届いた」と「人から聞いた」では検証の重みが違う。

**Q2A-5. 差し支えなければ、状況を詳しくお聞かせください**（段落・任意）
> 説明文：「〇月末で退職して、△△市の国保に入ったら通知書が□円だった」のように書いていただけると助かります。お名前や会社名はご記入なさらないでください。

## 4. サイト側の実装

### 4.1 URLの組み立て

```javascript
// js/feedback.js
const FORM_BASE = 'https://docs.google.com/forms/d/e/{FORM_ID}/viewform';

// Googleフォームの各質問の entry ID（フォーム作成後に取得して設定する）
const ENTRY = {
  category: 'entry.0000000001', // Q1
  context:  'entry.0000000002', // Q3-1
};

function openFeedbackForm(category) {
  const payload = { category, context: buildContextSummary() };
  assertNoSensitiveData(payload); // 仕様書13.4のガード

  const params = new URLSearchParams({
    'usp': 'pp_url',
    [ENTRY.category]: CATEGORY_LABELS[category], // 選択肢の表示文字列と完全一致させる
    [ENTRY.context]: payload.context,
  });

  window.open(`${FORM_BASE}?${params}`, '_blank', 'noopener,noreferrer');
}
```

> **⚠️ 実装上の注意**
> ラジオボタンを事前入力する場合、**選択肢の表示文字列と完全に一致していないと反映されない。** 半角・全角、句読点まで一致させること。`CATEGORY_LABELS` は選択肢の文字列をそのまま持たせる。

### 4.2 entry ID の取得手順

1. 作成したフォームを開き、右上の「⋮」→「事前入力したURLを取得」
2. 各質問に仮の値（例：`TEST_CATEGORY`）を入力して「リンクを取得」
3. 生成されたURLの `entry.XXXXXXXXX=TEST_CATEGORY` から数字部分を控える

### 4.3 送信前の透明性表示

フォームへ遷移する**前に**、サイト側で以下を表示する（仕様書13.3）。

```html
<div class="feedback-consent">
  <p>ご報告フォームを開きます。次の情報が一緒に送られます。</p>
  <code class="context-preview">V:v17.2|RY:令和8年度|RD:2026-09-30|PF:大阪府|…</code>
  <p class="note">お名前・ご連絡先・生年月日・お勤め先などは含まれていません。</p>
  <button type="button" id="btnOpenForm">フォームを開く</button>
  <button type="button" id="btnCancelFb">やめる</button>
</div>
```

### 4.4 3つの入口からの遷移

| 入口 | 遷移時の `category` |
|---|---|
| 結果画面「🤔 よく分からなかった」 | `usability` |
| 結果画面「😥 実際と違った」 | `calc_mismatch` |
| FAQ末尾「🤔」 | `content_error`（＋FAQ IDを context に付加） |
| フッター「間違いを見つけた・要望を送る」 | 未選択（セクション1で選ばせる） |

## 5. 集計スプレッドシートの設計

Googleフォームの回答シートに、以下の**作業用の列を手動で追加**する。

| 列 | 名称 | 用途 |
|---|---|---|
| A〜 | （フォームの回答） | 自動生成 |
| +1 | **再現確認** | 未確認 / 再現した / 再現しない / 情報不足 |
| +2 | **原因分類** | 料率テーブル / 計算ロジック / 表現 / 制度改正 / ユーザーの誤解 / 仕様通り |
| +3 | **対応状況** | 未対応 / 対応中 / 修正済 / 対応不要 |
| +4 | **修正バージョン** | v17.3 など |
| +5 | **changelog掲載** | 済 / 未 |

### 分析用の関数例

```
# 条件サマリから都道府県だけを抽出する
=REGEXEXTRACT(C2, "PF:([^|]+)")

# 判定結果だけを抽出する
=REGEXEXTRACT(C2, "VD:([^|]+)")

# 表示額と実額の差
=IF(AND(ISNUMBER(D2),ISNUMBER(E2)), E2-D2, "")
```

## 6. 週次レビューの手順

仕様書13.7の運用サイクルを、Phase 1向けに具体化したもの。**所要時間は週30分程度を想定。**

| 手順 | 内容 |
|---|---|
| **1. `calc_mismatch` を全件確認** | 同じ条件を自分で入力し、再現するか確かめる |
| **2. 再現したものを原因分類** | 料率の誤り／ロジックの誤り／レンジ設定が狭すぎる／仕様通り（説明不足） |
| **3. 「仕様通り」が多い項目を洗い出す** | 計算は正しいのに誤解されている＝**説明の問題**。FAQか結果画面の文言を直す |
| **4. `content_error` の出典を確認** | 一次情報（厚労省・日本年金機構・協会けんぽ・国税庁）で裏を取る |
| **5. `feature_request` を集計** | 同じ要望が3件を超えたらロードマップへ |
| **6. changelog を更新** | 修正した内容を1行で記載する |

### 「仕様通りだが誤解されている」への対応が最も重要

計算が正しいのに「違っていた」と報告されるケースは、**説明が伝わっていないというより価値の高いシグナル**である。数字を直すより、次のいずれかで対応する。

- 結果画面の内訳表示を増やす
- 該当するFAQを第1層（文脈連動）に昇格させる
- 用語ミニ解説を追加する

## 7. Phase 2 への移行

### 移行の判断基準

| 指標 | しきい値 |
|---|---|
| 週あたりの回答件数 | 5件を超えたら検討 |
| フォームへの遷移率 | 遷移前に離脱している割合が高い場合は前倒し |
| 👍のカウントが必要になったとき | Phase 1では取得できないため |

### 項目の対応表

Phase 2（Cloudflare Pages Functions）へ移る際、Googleフォームの各質問はそのままJSONのキーに対応させる。**過去データと接続できるよう、名称を変えないこと。**

```javascript
{
  category: 'calc_mismatch',      // Q1
  item: 'kokuho',                 // Q2A-1
  displayedAmount: 20150,         // Q2A-2
  actualAmount: 18400,            // Q2A-3
  source: 'municipality',         // Q2A-4
  freeText: '…',                  // Q2A-5
  context: 'V:v17.2|RY:…',        // Q3-1
  createdAt: '2026-09-10T12:00:00Z',
}
```

### Phase 2で追加できること

- 👍のカウント（離脱なしでその場送信）
- FAQ項目ごとの「🤔率」の自動集計（仕様書14.7の改善サイクルが回せるようになる）
- 結果画面から離れずに回答できるインライン展開

## 8. やらないこと（Phase 1・2共通）

- 第三者への提供
- 送信内容を用いた広告配信
- 体調に関する情報の送信（仕様書13.4の禁止項目）
